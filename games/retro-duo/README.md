# Retro Duo

An NES, Game Boy, Game Boy Color and Nintendo DS player for iPhone, built for iPhone Duo.

**License:** GNU GPL v3 or later (see `LICENSE`), because the DS engine, melonDS, is GPL. Nestopia is GPL v2 or later; SameBoy is Expat (MIT); teakra is MIT.

- **Emulation:** the [SameBoy](https://github.com/LIJI32/SameBoy) core (Expat/MIT license), compiled straight into the app. Every game runs on an emulated Game Boy Color, so original Game Boy games get color palettes.
- **iPhone Duo:** fold it halfway (laptop style) and the picture sits on the top half with the controls on the bottom half. Flat landscape puts the D-pad and buttons on either side. Portrait works like the original handheld.
- **Hinge control (iPhone Duo):** Settings › Hinge control turns the fold into a control while the Duo is partly open: *Squeeze for a button* (fold a little shut to press a chosen button) or *Steer* (fold shut for left, open wider for right). The resting angle is learned from how the phone is held once it settles (`HingeGesture.swift`, checked on CI with simulated hinge movements).
- **Library:** tap **+** to import `.gb` / `.gbc` files, or drop them into Files › On My iPhone › Retro Duo. Swipe to delete.
- **Saves:** in-game saves are written automatically (Files › Retro Duo › Saves). The game also resumes where you left off, and the ☰ menu has a quick save slot.
- **Extras:** haptics, rumble carts, sound, and Bluetooth controllers (right face button = A, bottom = B, Menu = START, Options = SELECT).
- **Nintendo DS:** [melonDS](https://melonds.kuribo64.net) 1.1 with its free replacement BIOS (no Nintendo files needed), running on its own thread. Half-folded, the top screen sits above the fold and the touch screen below it, between the D-pad and A/B/X/Y. L/R are on screen and on controllers' shoulder buttons. Saves, resume and quick save work like Game Boy.
- **Game Boy Advance:** [mGBA](https://mgba.io) 0.10.5 (MPL 2.0) with its built-in BIOS replacement, in the single-screen play view with on-screen L/R. Vendored sources are compiled through `ios/RetroDuo/GBACore/units` (one generated file per source, see `tools/make_units.py`) so every object file has a unique name; mGBA's bundled blip_buf is renamed in `GBAConfig.h` because melonDS ships the same library.
- **Super Nintendo:** [bsnes](https://github.com/libretro/bsnes-libretro) (GPLv3) with its fast PPU and DSP, run through a small libretro host (`ios/RetroDuo/Libretro`) that later libretro cores can reuse. libco's ARM64 context switch is rebuilt as a normal function (`SNESCore/RDLibco.c`) because iOS doesn't allow making data executable. bsnes's bundled Super Game Boy SameBoy and its `retro_*` functions are renamed in `SNESConfig.h` so they don't clash with the app's SameBoy or other cores.
- **Sega Genesis / Mega Drive, Master System and Game Gear:** [BlastEm](https://github.com/libretro/blastem) (GPLv3) through the same libretro host; the file extension (.md/.gen/.smd, .sms, .gg) picks the console. Its 68000, Z80, SH-2 and uPD78K2 interpreters are generated by BlastEm's `cpu_dsl.py` before each build (`tools/generate_blastem.py`, run by CI; the 68000 core alone is ~56 MB of C, so it isn't committed). Every BlastEm global (~1200, including its own zlib and LZMA) is renamed with a `blastem_` prefix in `SegaCore/SegaConfig.h`; after updating BlastEm, rebuild its objects and regenerate that list from `nm`. Three small fixes are made to the vendored BlastEm (listed in `vendor/blastem/UPSTREAM.txt`): the Z80's usual RETN encoding (ED 45) decoded as a no-op, so a Master System PAUSE froze games; PAUSE re-fired forever; and START is wired to the Master System's console PAUSE button.
- **NES:** [Nestopia UE](https://github.com/0ldsk00l/nestopia), the accurate NES core, running in the same single-screen play view as Game Boy (8:7 picture, overscan cropped).
- **Second-screen tracker:** the chart button in the top bar swaps the lower screen's controls for live stats read from the game's memory a few times a second (a Bluetooth controller and the hinge still play). Definitions live in `ios/RetroDuo/Resources/Trackers.json`: per-game stats (binary, BCD, digit, bit-count and named values, joined parts such as world 4-2 or a play clock) and a party list. Included: Pokémon Red/Blue, Yellow, Gold/Silver and Crystal (party with nicknames, levels and HP, badges, Pokédex, money, play time; USA addresses from the pret disassemblies), Super Mario Bros., Super Mario World, Sonic the Hedgehog, and the built-in test carts (checked by CI). Games without a definition show the session's basics. Each core exposes its work RAM for this: SameBoy `GB_safe_read_memory`, Nestopia's CPU RAM, mGBA `rawRead8`, and libretro `RETRO_MEMORY_SYSTEM_RAM` (bsnes's port was patched to expose it, and its battery RAM, so SNES saves are now kept per game by the app; BlastEm's Genesis RAM is 16-bit words in host order). `tests/tracker` checks the definitions against memory laid out the way each game keeps it.
- **Live streaming:** Game menu › **Go live** streams to Twitch, YouTube, Kick or any RTMP server with your stream key (kept in the Keychain). Viewers get the clean game picture (720p, 30 fps, sharp pixels; the DS's two screens side by side), the game's sound even when it's muted on the phone, and optionally your voice. A red LIVE badge with a timer sits in the top bar. Everything is built in with Apple frameworks: a small RTMP/RTMPS client on Network.framework (`LiveRTMP.swift`), hardware H.264 and AAC (`LiveEncoders.swift`) and a clock-paced mixer (`LiveStreamCore.swift`), so the stream keeps going while the game is paused. `tests/live` streams a test picture and tone to a stand-in RTMP server (`fake_rtmp_server.py`, itself checked against ffmpeg) that checks the H.264/AAC it receives, and a refused key.
- **Stream extras:** while live, the tracker shows on the stream itself (a card beside the game, under the DS's screens, or over the corner when the picture fills the frame; Live stream › "Show the tracker on stream"). The 🎞 button next to the LIVE pill saves the last 30 seconds to Photos exactly as viewers saw and heard them (kept encoded in memory, written to MP4 without re-encoding: `LiveClips.swift`). With your channel name under Live stream › Chat, the 💬 button puts Twitch, Kick or YouTube chat (the platform's pop-out chat, so you can reply once signed in) on the lower screen; YouTube's is found from your @handle once the video is live, or from a pasted link. `tests/live` checks the card's placement and drawing, saves a real clip from the stand-in stream and checks it plays, and checks the chat links.
- **Home screen widget:** "Continue playing" in small (last game's box art), medium (last game plus two more) and lock screen sizes; tapping opens the game through `avydrix://play?id=…`. The app and the widget (`RetroDuoWidget/`) share the recent list in a Keychain access group (`WidgetShelf.swift`) because App Groups can't be created through Apple's API, which CI uses to register the widget's app ID and App Store profile alongside the app's.
- **Rewind & fast-forward:** hold ⏪ in the top bar to step back through the last ~10 seconds (LZ4-compressed save states, 10 a second; the DS takes one every half second in the background), tap ⏩ for 2×/3×/4× speed (Game settings › Rewind & fast-forward). Sound is muted meanwhile and the queued sound is dropped afterwards so it stays in sync. `tests/rewind` checks the history; a UI test checks both on the test cart.
- **Two players:** with two Bluetooth controllers on a NES, SNES, Genesis or Master System game, the second plays as player 2 (controller 2 port; Nestopia `pad[1]`, libretro port 1) and the controllers' player lights show 1 and 2. Touch controls and the hinge stay player 1.
- **Cheats:** Game menu › Cheats adds codes per game, each with an on/off switch; codes the console doesn't understand are flagged. Game Boy / Color: Game Genie and GameShark (SameBoy's `cheats.c`, now vendored). NES: Game Genie, Pro Action Rocky and `AAAA:VV` RAM codes (Nestopia). SNES: Game Genie and Pro Action Replay (bsnes's `retro_cheat_set`). GBA: GameShark, Action Replay and CodeBreaker (mGBA). DS: Action Replay DS (melonDS's AR engine). Genesis / Master System / Game Gear: Action Replay RAM codes, written by the app each frame since BlastEm has no cheat engine (Game Genie isn't supported there yet). Each core's test checks that a code really changes the game; `tests/cheats` checks parsing.
- **iCloud save sync:** Settings › iCloud keeps in-game saves and save states in the app's private iCloud Drive folder, so they follow you to another iPhone and survive a reinstall (games aren't uploaded). Sync runs on launch, when the app is put away and after a game closes, never mid-game; file by file the newer copy wins and nothing is deleted (`SaveSync.swift`, checked by `tests/savesync` against a stand-in folder). It needs the iCloud container `iCloud.com.ctnetworkstudios.retroduo` on the app's App ID; until the App Store profile allows it, CI ships the build without iCloud (`tools/strip_icloud.py`).
- **RetroAchievements:** sign in under Settings › RetroAchievements (a free retroachievements.org account) and games the site recognizes award achievements as you play: a toast pops up on each unlock, and the command center's ACHIEVEMENTS tile lists them with badges and progress. Casual (softcore) mode, so rewind, cheats and save states keep working. Built on [rcheevos](https://github.com/RetroAchievements/rcheevos) 12.5 (MIT, `vendor/rcheevos`, compiled through `Achievements/units`) with a small C layer (`Achievements/RDAchievements.c`) that maps RetroAchievements' memory addresses onto each core's, and Swift doing the web requests and keeping the sign-in token in the Keychain. `tests/run_achievements_test.sh` signs in, identifies a game by hash and unlocks an achievement against a stand-in server; the DS core test checks main RAM reads.
- **Controller mode:** connect a Bluetooth controller (SCUF, Xbox, PlayStation, Backbone…) and the touch controls disappear: the game fills the screen at its own proportions (DS: both screens, the touch screen still touchable), with the tracker or chat beside or under it when open and there's room. Folded like a laptop, the game keeps the upper screen and the lower one shows the tracker, chat or a menu reminder. Home on the controller (or both sticks clicked) opens the game menu; a tap shows the top bar for a few seconds. Settings: when a controller is connected (default), always, or off; also a CONTROLLER MODE tile in the game menu (`ControllerMode.swift`).
- **Built-in Test Cart:** an original mini ROM for checking controls, sound and colors on first launch.
- **Free built-in game: Grave Mistakes**, a chaotic funeral home sim for the DS screens: the funeral home live on top, bookings, body prep and quick fixes on the touch screen. Source in `games/funeral-home-ds`.

The app ships no commercial games. Players add games they own or that are shared freely.

## Getting it on TestFlight

1. Merge the pull request. GitHub's Mac builds the app and a Linux machine plays the test cart to check the emulator.
2. One time only: in App Store Connect go to **Apps → + → New App**, name it **Retro Duo** and pick bundle ID `com.ctnetworkstudios.retroduo`. (The upload step registers the bundle ID for you if it isn't listed yet. Run it once and it will appear.)
3. Go to **Actions → Retro Duo TestFlight → Run workflow** on `main`. The build appears in TestFlight a few minutes later.

The upload uses the same `ringside-testflight` signing secrets as the other games.

## Layout

| Path | What it is |
|---|---|
| `ios/RetroDuo/*.swift` | SwiftUI app: library, play screen, controls, audio, saves |
| `ios/RetroDuo/Core/RDCore.c/.h` | Small C layer between Swift and SameBoy |
| `ios/RetroDuo/Core/SameBoyConfig.h` | SameBoy build options (prefix header) |
| `ios/RetroDuo/Resources/` | Game Boy Color start-up ROM (built from SameBoy source), test cart, license |
| `ios/RetroDuo/DSCore/` | C bridge and platform layer for melonDS (`MDCore`) |
| `vendor/melonDS/` | melonDS 1.1 core sources (no frontend, JIT or OpenGL) |
| `testcart-ds/` | Original DS test cart (C, built with stock clang + lld) |
| `ios/RetroDuo/NESCore/` | C bridge for Nestopia (`NESCore`) |
| `vendor/nestopia/` | Nestopia UE core sources (no frontend) |
| `testcart-nes/` | Original NES test cart, built by `make_cart.py` with a tiny Python 6502 assembler |
| `ios/RetroDuo/GBACore/` | C bridge for mGBA (`RDGBA`) and the generated compile units |
| `ios/RetroDuo/Libretro/` | Libretro host (`RDLibretro`): video, audio, input, options and saves for libretro cores |
| `ios/RetroDuo/SNESCore/` | bsnes build options, iOS-safe libco, the core table and generated compile units |
| `ios/RetroDuo/SegaCore/` | BlastEm build options and renames, the core table and generated compile units (`generated/` is made at build time) |
| `vendor/mgba/` | mGBA GBA core sources |
| `vendor/bsnes/` | bsnes (libretro port) SNES core sources |
| `vendor/blastem/` | BlastEm (libretro port) Sega core sources |
| `testcart-gba/` | Original GBA test cart (C, built with stock clang + lld) |
| `testcart-snes/` | Original SNES test cart (65816 in 6502 emulation mode, built with `testcart-nes/asm6502.py`) |
| `testcart-sega/` | Original Genesis (C, built with clang for the 68000 and a small Python linker), Master System and Game Gear (Z80, small Python assembler) test carts |
| `tools/make_units.py` | Regenerates the per-source compile units for vendored cores |
| `vendor/SameBoy/` | SameBoy v1.0.5 `Core/`, unmodified |
| `testcart/` | Test cart source (RGBDS assembly) and `build.sh` |
| `ios/RetroDuo/Resources/GraveMistakes.nds` | Built from `games/funeral-home-ds` (BlocksDS); CI checks it matches the source |
| `tests/` | Headless core test run on every push |

## Updating SameBoy

Replace `vendor/SameBoy/Core` with the new release's `Core` folder (minus `debugger.c`, `sm83_disassembler.c`, `symbol_hash.c`, `cheats.c`, `cheat_search.c`, `rewind.c`), update `GB_VERSION` in `SameBoyConfig.h`, rebuild `cgb_boot.bin` with `make bootroms`, and run `tests/run_core_test.sh`.
